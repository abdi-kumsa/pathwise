Foundation — Database

What the Database Looks Like

Four tables are live and ready to receive data. All indexed for the queries the dashboards will run.

students
Student profile per record: GPA, internship count, projects, communication score, program, enrollment year
enrollments
Year-over-year intake count per program — the time-series the enrollment forecast model will train on
job_postings
Employer listings: company, role, location, salary range, required skills array (JSONB), source, posted date, internship flag
placements
Outcome records: which student, which company, salary, time-to-hire, placement status — the ML model's ground truth

Schema is already deployed to PostgreSQL. ORM models in Python mirror every column — the API layer talks to the database through these, not raw SQL.

Coming Up — Phase 2

Data Pipeline & Feature Engineering

1
generate_mock_data.py
Creates realistic synthetic records for students, job postings, enrollments, and placements using Faker. Produces CSV files that mirror real institutional data.
2
load_to_db.py
ETL script that ingests the generated CSVs into PostgreSQL. Handles transformation, validation, and bulk loading into the four tables.
3
feature_engineering.py
Produces lag features, rolling averages, and seasonality encoding. Outputs processed parquet files ready for ML model training in Phase 3.
4
data_quality_check.py
Validates loaded data — row counts, null checks, range validation — and produces a summary report confirming the pipeline is healthy.

Why mock data first? Building with synthetic data lets us prove every dashboard works end-to-end before real institutional data is available. When real data arrives, it's a swap — not a rebuild.

Decision Point

A Note on Data

One important decision to confirm today, as it shapes how Phase 2 is built:

A
Synthetic Data
We generate everything
  • Fastest path to a full demo
  • Fully demonstrable from day one of Phase 3
  • Clearly labeled as simulated in the UI
  • Real data can be swapped in at any point
B
Real Institutional Data
You provide the data
  • Models train on actual patterns
  • Results reflect your real institution
  • Needed in CSV or DB export format
  • Must arrive by Week 5 (start of Phase 3)

Either path works. We just need to align today so Phase 2 is built correctly. If real data is expected, please confirm the format and what records are available (enrollment history years, job posting sources, placement outcome data).
