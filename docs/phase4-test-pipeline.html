System Architecture Under Test
Phase 4 introduces the API layer bridging the ML pipeline to the React frontend
FastAPI Backend
  • 2 routers: /api/market & /api/enrollment
  • 13 endpoints total (7 market + 6 enrollment)
  • Pydantic v2 request/response schemas
  • CORS middleware for React frontend
  • Running on port 8080
ML Service Layer
  • Lazy singleton pattern (load once per process)
  • XGBoost placement prediction + SHAP
  • LSTM enrollment forecasting
  • Prophet demand forecasting
  • sys.path injection for ml/ imports
Data Services
  • market_service.py — 7 functions from CSV + SHAP
  • enrollment_service.py — 6 functions from parquet
  • Skill gap: SHAP normalised to 0–100 demand score
  • Admission risk: YoY enrollment decline %
  • Placement coverage from 3,000-student dataset
React Frontend
  • 8 new pages wired to live API
  • Recharts v3: BarChart, AreaChart, LineChart
  • SHAP waterfall with per-bar Cell coloring
  • LSTM line chart with historical/forecast overlap
  • Vite build: 523 modules, 0 errors
Error Handling
  • 422 Unprocessable Entity — missing/invalid fields
  • 404 Not Found — unknown programme in forecast
  • 500 prevention — all edge inputs return non-500
  • Extra fields silently ignored (Pydantic default)
  • GPA boundary inputs (2.0, 4.0) handled correctly
Test Infrastructure
  • Pure stdlib: urllib.request, json
  • No pytest dependency — runs anywhere Python is available
  • File: tests/test_phase4.py
  • Self-contained — one file, no fixtures
  • 60 s timeout per request (SHAP/LSTM calls)
