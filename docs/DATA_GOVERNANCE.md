# Data governance — retention, export and erasure

What PathWise keeps, for how long, how to export it, and how to erase it.
Plan item 4.4 of [audit/2026-11-07-improvement-plan.md](audit/2026-11-07-improvement-plan.md).
Every action below that changes or removes data is written to the audit log.

## What is stored

| Store | Contents | Personal data |
|---|---|---|
| `users` (Postgres) | Username, display name, role, institution, programme, password hash, token version | Yes |
| `audit_log` (Postgres) | Actor, role, action, resource, payload, time | Yes (actor) |
| `scenarios` (Postgres) | Policy what-ifs: owner, assumptions, status | Owner username |
| `expert_validations` (Postgres) | Expert name, organisation, verdict, notes, who recorded it | Yes (expert) |
| `ahp_matrices` (Postgres) | Pairwise matrices and consistency ratios | No |
| `data/ethiopia/*.parquet` | Fact tables, simulated until official files are ingested | No individual records |
| `data/monitoring/predictions.jsonl` | Leftover US placement inputs (only with `LEGACY_US_MODELS=1`) | Profile inputs, no identity; not committed to git |

## Retention

| Data | Kept | Removed by | Setting |
|---|---|---|---|
| Audit log | 365 days | Daily job and `POST /api/admin/audit-log/purge` | `AUDIT_RETENTION_DAYS` (minimum 30) |
| Draft and rejected scenarios | 180 days | Daily job | `SCENARIO_RETENTION_DAYS` (minimum 30) |
| Submitted, approved, archived scenarios | Indefinitely | Not purged: part of the governance record | — |
| Expert validations | Indefinitely | Demonstration rows only, via *Clear demonstration rows* | — |
| Users | Until erased | Administrator | — |
| Ingested official files | The current file plus every replaced version in `data/ethiopia/_backup/` | Manual | — |

Each purge writes one audit row (`audit_retention` / `scenario_retention`) with
the number removed and the cutoff, so the record of what was removed survives
the removal.

## Export

| What | How |
|---|---|
| Audit log | Admin → Audit log (search, then copy); `GET /api/admin/audit-log?limit=1000` |
| Workforce planning report | MoL → Workforce report → CSV / XLSX / PDF (audited `report_export`) |
| Expert validations | Admin → Methodology → *Export CSV* (audited `report_export`) |
| Model comparison and importance | `docs/MODEL_COMPARISON.md`, `docs/FEATURE_IMPORTANCE.md`, regenerated by `scripts/model_report.py` |
| Ingestion history | `data/ethiopia/ingestion_log.json` |

## Erasure

| Request | Action |
|---|---|
| Remove a user's access | Deactivate (reversible; sessions end within 30 seconds) |
| Erase a user | `DELETE /api/users/{username}/permanent`. Audit rows naming them as actor are kept until the retention window removes them, because the log must show who did what |
| End every session of a user | Reset their password or change their role; the token version increments |
| Remove an expert's record | Delete the `expert_validations` rows for that expert (database), then re-export |

## Sessions

Tokens last 8 hours (`JWT_EXPIRE_MINUTES`) and are refreshed by the frontend
while a user is active. Each carries a version number: a password change, role
change or institution change increments it, which invalidates every token
issued before. Deactivation takes effect within 30 seconds, and immediately
when made through the admin console.
